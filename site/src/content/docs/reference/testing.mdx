Automated evidence recorded on August 14, 2026 for `v0.3.0`: **165 tests passed** across Chromium, Firefox, and WebKit with Playwright and axe-core.

## Automated coverage

The browser suite exercises both tab profiles, actual focus, keyboard activation, URL fragments, nested and custom element names, disconnect/reconnect, `refresh()`, generated and preserved IDs, malformed markup, duplicate IDs, axe checks, and ARIA snapshots.

Carousel coverage includes parser-safe bootstrap initialization, authored initial visibility, manual previous/next actions, finite and looping boundaries, stable focus, action-based change events, refresh precedence, nested ownership, dialog composition, live-region semantics, named slides, malformed controls, IDREF validation, axe, and ARIA snapshots.

Form coverage includes native fallback, first-invalid focus with normal scrolling, author-owned errors and summaries, ARIA restoration, fieldset radio groups, custom ownership, lifecycle, malformed relationships, and a canonical axe fixture.

The suite also covers reset and canceled-reset behavior, first-visible invalid focus, the `manner-form-invalid` event, conditional panel tab stops, authored `tabindex` preservation, disabled controls, and opt-in `hidden="until-found"` behavior.

Panel tab-stop coverage includes `<summary>` and `<iframe>` as focus targets, every negative `tabindex` value, hidden inputs, and controls disabled by an ancestor `<fieldset disabled>`.

npm run test:browser

## Manual assistive-technology matrix

Automated results do not establish assistive-technology support. Carousel was a completion gate; the v0.3.0 manual matrix below records the required pass for slide announcements and stable focus in all three combinations.

| Platform | Browser | Assistive technology | Status |
| --- | --- | --- | --- |
| macOS | Safari | VoiceOver | Pass — user-verified |
| Windows | Firefox | NVDA | Pass — user-verified |
| Windows | Chrome | NVDA | Pass — user-verified |
| iOS | Safari | VoiceOver | Unverified |
| Android | Chrome | TalkBack | Unverified |

For the three required Carousel combinations, a pass requires a named slide change to be announced after activating Previous or Next, focus to remain on that navigation button, finite boundaries to be understandable, and `data-loop` wrapping not to produce duplicate or stale announcements. The v0.3.0 gate passed those checks. Mobile screen-reader behavior remains unverified.

## Release interpretation

The automated suite and the completed desktop manual matrix support the v0.3.0 release claim. Mobile screen-reader behavior is still outside this evidence and remains unverified.
